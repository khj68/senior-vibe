운영 원칙

학생별 경험 차이가 크기 때문에 모두에게 같은 과제를 주면 안 됩니다. 대신 팀별 공통 학습을 짧게 깔고, 각자 하나의 작은 산출물을 맡겨서 2주 안에 “이 학생이 어디까지 가능한지” 확인하는 구조가 좋습니다.

공부는 산출물과 묶기

자료만 던지지 말고, 학습 결과를 실험 노트, 화면 시안, 점수 로직, 테스트 케이스로 남기게 합니다.

학습 기록 작은 데모

의료 표현은 보수적으로

오십견, ROM, 어깨 나이 표현은 자가 체크와 생활습관 참고로 한정하고 진단처럼 보이지 않게 합니다.

자가 체크 진단 금지

2주마다 계속/전환 판단

기술 적합도는 말보다 산출물로 판단합니다. 2주 결과를 보고 역할을 유지하거나 더 쉬운 범위로 재배치합니다.

주간 데모 역할 조정

공통 사전학습

두 팀 모두 시니어바이브가 무엇을 하는지, 사용자가 어떤 불안을 갖는지, 어떤 표현을 조심해야 하는지부터 맞춰야 합니다.

도메인 이해

  • 오십견의 일반적인 증상과 어깨 가동범위 제한이 사용자 경험에서 어떤 의미인지 파악
  • ROM은 진단값이 아니라 움직임 범위를 참고하는 지표라는 관점 이해
  • 키오스크, 카메라 측정, 결과 리포트가 사용자에게 어떤 흐름으로 보이는지 정리

제품/윤리 기준

  • 의료적 진단, 치료 효과 보장, 정확도 과장 표현 금지
  • 카메라 권한, 개인정보, 영상 저장 여부를 사용자에게 명확히 설명하는 방식 학습
  • 모든 데모는 익명 샘플 데이터와 테스트 계정 기준으로 제작

협업 기본기

  • GitHub Issue, branch, pull request, review comment 흐름 실습
  • 매주 “이번 주 한 일, 막힌 것, 다음 주 산출물” 3문장 업데이트 작성
  • 실험/구현 결과를 재현 가능한 링크, 캡처, 표 형태로 남기는 습관 만들기

사용자 관점

  • 어깨 불편을 느끼는 40~60대 사용자와 자녀 세대가 각각 어떤 문구에 반응할지 비교
  • “무섭게 경고하는 서비스”보다 “가볍게 체크하고 다음 행동을 권하는 서비스” 톤 익히기
  • 검사 결과보다 공유하고 싶은 결과 카드가 무엇인지 리서치

R&D/ROM 팀 사전학습

이형진과 박하준은 실제 제품의 본체 기술에 가까운 팀입니다. 이 팀은 “논문처럼 멋진 모델”보다 측정 조건, 실패 케이스, 재현 가능한 실험 로그를 만드는 것이 먼저입니다.

이형진 중심

컴퓨터비전/모델 학습

  • MediaPipe Pose, MoveNet, YOLO Pose처럼 웹캠 영상에서 관절 keypoint를 뽑는 방식 비교
  • 사전학습 모델을 그대로 쓸 때와 일부 head만 붙여 보정할 때의 차이 정리
  • 어깨 외전, 굴곡, 좌우 비대칭처럼 ROM 계산에 필요한 기본 기하 이해
  • 조명, 옷 색상, 카메라 거리, 팔 가림, 측면/정면 자세에 따른 실패 유형 정리

박하준 중심

측정 환경/기기 관점

  • 카메라 해상도, 촬영 거리, 키오스크 설치 높이, 사용자 안내 문구가 측정 품질에 미치는 영향 정리
  • 임베디드/기기 개발 관점에서 입력, 처리, 출력, 로그 저장 흐름 그리기
  • 실험 참여자에게 어떤 자세 안내가 필요한지 스크립트 작성
  • 수학적 각도 계산을 그림으로 설명하고, 사람이 봐도 이해되는 검증표 만들기

바이럴 MVP 팀 사전학습

손민준, 이여진, 이수빈은 “어깨 나이 테스트”를 작은 제품처럼 만들어야 합니다. 카메라 측정은 선택 기능이고, 사용자가 끝까지 완료하고 공유하고 싶게 만드는 흐름이 더 중요합니다.

  • 카메라 권한 요청, 측정 안내, 실패 안내 문구를 사용자 흐름으로 정리
  • 프롬프트 엔지니어링으로 결과 해석 문구를 부드럽게 만드는 실험

산출물 아이디에이션

산출물은 “잘 공부했습니다”가 아니라 대표가 바로 볼 수 있는 링크, 표, 캡처, 데모 형태여야 합니다.

팀 산출물 담당 후보 완료 기준
R&D/ROM ROM 측정 실험 노트 이형진 샘플 영상, 추출 keypoint, 계산 각도, 실패 원인이 한 표에 정리됨
R&D/ROM 측정 환경 체크리스트 박하준 카메라 거리, 조명, 자세 안내, 재촬영 조건이 문서화됨
R&D/ROM 실패 케이스 갤러리 이형진 + 박하준 왜 측정이 틀어지는지 이미지와 원인 태그로 설명 가능
바이럴 MVP 어깨 나이 점수표 손민준 OX 답변과 카메라 측정 여부에 따라 결과 타입이 안정적으로 나뉨
바이럴 MVP 카메라 측정 사용자 흐름 이여진 허용, 거부, 실패, 재시도, 건너뛰기 화면이 모두 정의됨
바이럴 MVP 게임형 설문/결과 UI 이수빈 모바일에서 진행률, 선택지, 결과 카드가 깨지지 않게 보임
바이럴 MVP 공유 문구/CTA 세트 손민준 + 이여진 의료 과장 없이 공유하고 싶은 결과 문구와 정밀 측정 권유 문구가 준비됨

2주 온보딩 체크리스트

첫 2주는 완벽한 구현보다 학습 속도, 협업 습관, 문제를 쪼개는 능력을 확인하는 기간으로 둡니다.

Day 1

도메인/보안 온보딩

오십견 서비스 흐름, 의료 표현 주의사항, 개인정보/카메라 권한 원칙을 공유합니다.

Day 2-3

팀별 기술 스파이크

R&D 팀은 pose estimation 샘플을, 바이럴 팀은 설문 결과 페이지나 Unity/Web 인터랙션 샘플을 실행합니다.

Day 4-5

첫 산출물 초안

각자 비교표, 문항표, 화면 상태표, 측정 환경표 중 하나를 만들고 팀 안에서 리뷰합니다.

Week 2

작은 데모와 역할 조정

대표가 볼 수 있는 캡처/링크/표를 만들고, 학생별 역할을 유지할지 조정할지 판단합니다.

학생에게 줄 첫 메시지

“2주 동안 완성품을 만들 필요는 없습니다. 대신 본인이 공부한 내용을 작게라도 재현 가능한 산출물로 남겨주세요. 좋은 산출물은 링크, 표, 캡처, 실패 원인이 같이 있는 것입니다.”

관리자가 볼 신호

좋은 신호는 질문이 구체적이고, 실패를 기록하며, 작은 단위로 결과를 공유하는 것입니다. 나쁜 신호는 공부만 오래 하고 결과물이 없거나, 의료 표현 리스크를 구분하지 못하는 것입니다.

학생 공통 메일 초안

다섯 명에게 공통으로 보낼 수 있는 버전입니다. 이름, 일정, 링크만 실제 발송 전에 바꾸면 됩니다.

  • 시니어바이브가 다루는 오십견/어깨 가동범위 측정 서비스 흐름 이해
  • 의료적 진단처럼 보일 수 있는 표현을 피하고, 자가 체크/생활습관 참고 수준으로 표현하는 기준 이해
  • GitHub Issue, branch, pull request를 통한 협업 방식 익히기
  • 본인이 공부한 내용을 재현 가능한 형태의 산출물로 남기는 연습

팀별 사전학습과 산출물 예시는 아래 문서에 정리해두었습니다. 각자 본인 역할에 가까운 부분을 먼저 읽어보고, 첫 미팅 때 “내가 2주 안에 만들어볼 수 있는 작은 산출물”을 하나씩 제안해주시면 좋겠습니다.
