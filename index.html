지원 문서 5건을 기준으로 학생별 장단점, 시니어바이브 제품군별 투입 적합도, 8주 실행 과제를 대표 공유용으로 정리했습니다. 원문 연락처는 제외했고, 실제 배포 페이지에는 의사결정에 필요한 내용만 남겼습니다.

키오스크/카메라 각도 측정 일본 파트너 멤버십 앱 운영 어드민 R&D 지원금 과제 산출물

결론 요약

바로 전력화 가능한 한 명에게 모든 것을 맡기기보다, R&D·앱·어드민을 작은 산출물로 쪼개 2~3명 조합으로 운영하는 편이 리스크가 낮습니다.

1순위: 이형진 카메라 기반 각도 측정과 의료 이미지 R&D에 가장 직접적으로 맞습니다.

Python LLM API Git 관리 보완 필요

시니어바이브 제품별 활용 방향

현재 해야 할 일은 서로 성격이 다릅니다. 학생 산학협력은 “핵심 제품의 책임 개발”보다 데이터 수집, 모델 검증, 화면 단위 구현, QA, 문서화처럼 분리 가능한 단위에 배치하는 것이 좋습니다.

오십견 키오스크/카메라 측정

각도 추정 정확도와 재현성을 높이는 R&D 과제입니다.

  • 이형진: OpenCV/PyTorch 기반 포즈·각도 추정 실험, 의료 이미지 전처리 리서치
  • 손민준: 측정 리포트 요약 자동화, LLM 기반 설명 문구 생성 실험
  • 박하준: 측정 로그 정리, Node/Express 기반 간단한 리포트 뷰 보조

일본 파트너 멤버십 앱

언어·현지화·사용자 흐름 검증이 중요합니다.

  • 이수빈: 일본어 기초 회화와 웹 경험을 활용한 문구 검수, 화면 QA
  • 이여진: JLPT N3, TOEIC Speaking 만점 기반 일본어/영어 문서 검수와 테스트
  • 손민준: 멤버십 안내 챗봇, FAQ/RAG 프로토타입 보조

통합 어드민

키오스크 데이터, 앱 회원, 리포트를 한 곳에서 다루는 내부 운영 도구입니다.

  • 박하준: HTML/CSS/JS, Node/Express 경험 기반 CRUD 화면 보조
  • 이형진: 측정 데이터와 모델 실험 결과를 볼 수 있는 분석 탭 설계 보조
  • 이수빈: 자료구조·웹 기초 기반 운영 매뉴얼/테스트 케이스 정리

학생별 장단점

점수는 시니어바이브의 현재 과제 적합도를 5점 만점으로 본 내부 참고값입니다. 성적 자체보다 “이번 제품군에 바로 쓸 수 있는 산출물” 기준으로 보았습니다.

이형진

Computer Vision, Multimodal AI, 의료 이미지 전처리 경험

4.7/5
R&D 핵심 PyTorch OpenCV 가능성 Git 협업
  • 장점: 딥페이크 탐지 모델 F1-score 0.72, 의료 AI 사업 참여, 혈관 탐지 방법 설계 등 영상/이미지 파이프라인 경험이 뚜렷합니다.
  • 활용: 어깨 관절 각도 측정 알고리즘 실험, 조명/거리/자세별 오차 분석, R&D 보고서용 실험 로그 정리에 투입합니다.
  • 주의: 실제 오십견 도메인과 키오스크 배포 환경은 별도 온보딩이 필요합니다. 군미필 일정 리스크도 확인해야 합니다.

손민준

AI/LLM/RAG, Python, API 기반 토이 프로젝트 다수

4.2/5
AI 자동화 Python Database Git 습관 보완
  • 장점: Gemini API, Notion API, Firebase, Spotify API 등 API 조합 경험이 많고, LLM 프롬프트 엔지니어링을 직접 해봤습니다.
  • 활용: 측정 결과 리포트 문구 자동 생성, 앱 FAQ/RAG, 운영 어드민의 데이터 요약 기능 프로토타입에 잘 맞습니다.
  • 주의: 본인이 Git 사용 미숙과 과거 프로젝트 유실을 언급했습니다. PR 단위 작업, 코드 리뷰, 이슈 템플릿을 강하게 잡아야 합니다.

이여진

시스템/리버스 엔지니어링 관심, 일본어·영어 강점

3.8/5
일본 파트너 QA C/C++ Git
  • 장점: TOEIC 990, TOEIC Speaking 200, JLPT N3로 일본 파트너와의 문구·요구사항 검수에 가장 강합니다.
  • 활용: 일본 앱 화면 문구 QA, 요구사항 번역 검토, 멤버십 플로우 테스트, 키오스크 장애 재현 및 로그 분석 보조에 적합합니다.
  • 주의: 웹/모바일 실무 경험은 문서상 제한적입니다. 구현보다는 QA, 분석, 문서화 중심으로 시작하는 편이 안정적입니다.

이수빈

Graphics, Computer Vision 관심, C/C++ 기초 탄탄, 일본어 가능

3.6/5
일본 앱 보조 C/C++ 웹 기초 실무 프로젝트 적음
  • 장점: 편입 전 성적이 높고, 자료구조 구현 경험과 Python 데이터 그래프 경험이 있습니다. 일본어 기초 회화도 가능합니다.
  • 활용: 일본 앱 QA 체크리스트, 어드민 테스트 케이스, 간단한 정적 페이지·운영 문서 작성에 적합합니다.
  • 주의: GitHub 기여도와 실무형 프로젝트 근거가 약합니다. 독립 개발보다 명확한 체크리스트형 과제로 배치해야 합니다.

박하준

의료SW/AI/Web 관심, Node/Express/MongoDB 개인 SNS 프로젝트

3.5/5
웹 보조 운영체제/xv6 React 학습 예정 초기 단계
  • 장점: Node.js, Express, MongoDB로 로그인·게시글·좋아요·권한 관리를 구현해본 경험이 있어 어드민의 기본 CRUD를 맡기기 좋습니다.
  • 활용: 리포트 출력 화면 보조, 어드민 테이블/필터 UI, 측정 데이터 CSV 다운로드 같은 범위가 명확한 기능에 적합합니다.
  • 주의: Git·프론트엔드 경험이 아직 낮고 동아리에서도 교육 단계입니다. 선임 개발자가 상세 기준을 주는 구조가 필요합니다.

8주 운영안

산학협력 학생에게는 넓은 목표보다 매주 확인 가능한 산출물이 중요합니다. 아래처럼 스프린트 단위를 작게 잡으면 대표가 중간에 계속 판단할 수 있습니다.

1주차

온보딩과 샘플 데이터 정리

오십견 측정 플로우, 키오스크 화면, 리포트 예시, 일본 앱 요구사항을 공유하고 학생별 담당 범위를 확정합니다.

2-3주차

작은 프로토타입 1차

각도 측정 실험 노트, 일본어 용어집, 어드민 정적 화면, 리포트 문구 자동화 중 각자 하나의 산출물을 냅니다.

4-5주차

데이터와 화면 연결

측정 샘플 데이터로 리포트/어드민 화면을 연결하고, 일본 앱은 파트너 확인 질문과 QA 기준을 정리합니다.

6-7주차

실패 케이스와 품질 기준

각도 측정 실패 유형, 리포트 표현 리스크, 앱 현지화 이슈, 어드민 데이터 누락 케이스를 정리합니다.

8주차

대표 보고 패키지

데모 URL, 실험 결과표, 다음 분기 개발 우선순위, 학생별 계속 활용 여부를 한 문서로 마감합니다.

운영 관리 포인트

권장 조합

R&D는 이형진을 중심으로 잡고, 손민준은 리포트 자동화와 LLM 실험에 붙입니다. 일본 파트너 앱은 이여진·이수빈을 QA/문구/요구사항 정리에 배치하고, 박하준은 어드민의 작은 화면 단위 구현으로 시작시키는 구성이 가장 현실적입니다.

계약·보안·품질

학생에게 원본 의료 데이터와 파트너 정보를 바로 열지 말고, 익명화 샘플 데이터와 테스트 계정부터 제공합니다. 모든 작업은 GitHub Issue, PR, 주간 데모, 산출물 체크리스트로 관리하고, R&D 결과는 재현 가능한 실험 로그 형태로 남기게 해야 합니다.
