결론 요약

산학협력은 “실무 보조”보다 “작은 제품과 실험을 끝까지 맡기는 구조”가 좋습니다. 특히 이번 미팅 기준으로는 핵심 R&D와 바이럴 실험을 분리해야 학생 역량도 살고 회사 산출물도 선명해집니다.

Track 1. R&D/ROM 고도화 이형진이 컴퓨터비전 실험을 리드하고, 박하준은 의료기기/임베디드 관점의 측정 환경과 데이터 수집 체계를 맡습니다.
Computer Vision ROM 측정 기기 실험 기록
Track 2. 바이럴 MVP 손민준, 이여진, 이수빈은 “어깨 나이 테스트”를 통해 오십견 도메인을 가볍게 체험시키는 웹 기반 서비스를 만듭니다.
OX 설문 카메라 선택 측정 공유형 결과
대표 확인 산출물 6~8주 뒤에는 ROM 실험 리포트, 바이럴 MVP 데모, 학생별 계속 활용 여부를 한 번에 판단할 수 있게 합니다.
데모 URL 실험 로그 운영 판단표

2-Track 팀 구성

두 팀은 결과물이 다릅니다. R&D 팀은 시니어바이브의 본체 기술을 고도화하고, 바이럴 팀은 고객 접점을 만드는 작은 제품을 빠르게 검증합니다.

Track 1

R&D/ROM 고도화 팀

본체 기술

오십견 관련 핵심 과제인 어깨 가동범위 측정, 측정 환경 정의, 모델 실험 로그를 맡깁니다. 의료적 진단이 아니라 측정 품질과 재현성 개선에 집중합니다.

이형진: CV/의료 AI 실험 리드 박하준: 측정 환경·기기 실험 기록
  • 카메라 거리, 각도, 조명, 자세별 측정 실패 케이스 수집
  • 사전학습 모델 기반 keypoint 추출과 ROM 계산식 비교
  • 키오스크/기기 환경에서 어떤 입력 품질이 필요한지 기준화

Track 2

바이럴 서비스 MVP 팀

고객 접점

대표님이 제안한 OX 테스트의 낮은 진입장벽을 살리되, 선택형 카메라 ROM 측정을 붙여 시니어바이브다운 기술 경험을 보여줍니다.

손민준: 자동화/API/결과 로직 이여진: AI 활용·인터랙션 이수빈: Unity/C#·상태 관리
  • “당신의 어깨 나이는?” 결과 페이지와 공유 문구 제작
  • OX 설문 기반 생활습관 점수와 선택형 카메라 측정 결합
  • 측정 실패 시에도 설문 결과만으로 완료되는 안전한 흐름 설계

추천 MVP: 어깨 나이 테스트

“카메라로 어깨 가동범위를 측정한다”는 아이디어는 좋습니다. 다만 바이럴 서비스에서는 권한 허용과 측정 실패가 이탈 요인이므로, OX 설문을 기본 흐름으로 두고 카메라 측정은 선택형 강화 기능으로 두는 하이브리드 구조를 권장합니다.

1

OX 설문

운동 습관, 통증 경험, 팔 올리기 불편감, 수면 자세 등으로 어깨 생활습관 점수를 만듭니다.

2

선택형 카메라 측정

원하는 사용자만 카메라를 켜고 팔 올리기/외전 동작을 촬영해 간단한 ROM 참고값을 받습니다.

3

결과 생성

어깨 나이, 주의 유형, 추천 스트레칭, 시니어바이브 정밀 측정 권유를 자가 체크용으로 제공합니다.

4

공유와 전환

친구에게 공유 가능한 결과 문구와 이미지, 키오스크/상담/측정 예약으로 이어지는 CTA를 붙입니다.

이 방식이 좋은 이유

설문만으로도 끝까지 갈 수 있어 진입장벽이 낮고, 카메라 측정을 선택한 사용자에게는 시니어바이브의 핵심 기술을 맛보기로 보여줄 수 있습니다. 학생들에게도 설문 로직, 카메라 인터랙션, 결과 생성, 공유 페이지라는 뚜렷한 역할 분리가 가능합니다.

표현상 주의

카메라 측정 결과는 의료적 진단처럼 보이면 안 됩니다. “자가 체크”, “생활습관 참고”, “정밀 측정 권장” 표현을 유지하고, 결과 화면에는 실제 진단은 전문가 상담과 기기 측정이 필요하다는 문구를 둡니다.

학생별 미팅 메모 기반 활용안

이번 버전은 지원서보다 미팅에서 확인한 실제 성향과 학습 단계에 가중치를 뒀습니다. 부족한 점을 숨기기보다, 어떤 오너십을 주면 성장과 산출물이 같이 나오는지에 초점을 맞췄습니다.

이형진

전 학과 인공지능학과, 컴퓨터비전, 의료 AI 경험

R&D
컴퓨터비전 파인튜닝 의료 AI
  • 강점: 딥페이크 탐지에서 모델 파인튜닝과 파이프라인을 맡았고, 의료 인공지능 경험도 있습니다.
  • 역할: 사전학습 모델에 프로젝트 데이터를 학습시키는 ROM 측정 실험, 실패 케이스 분석, 실험 리포트 작성.
  • 주의: 프론트/백엔드는 상대적으로 약하므로 웹 제품 구현보다 측정 알고리즘과 데이터 파이프라인에 집중시킵니다.

박하준

의료기기 시스템, 임베디드, 인공지능 기기 개발 관심

ROM
의료기기 임베디드 학습 속도 외향성
  • 강점: 아직 기술 전문성은 부족하지만 배우는 속도가 빠르고, 수학을 좋아하며 커뮤니케이션도 비교적 좋습니다.
  • 역할: 측정 환경 정의, 센서/기기 관점의 데이터 수집 플로우, 실험 기록, 현장 피드백 정리.
  • 주의: 3학년이고 기술 스택 학습 단계라 핵심 알고리즘 단독 구현보다 이형진과 페어로 성장시키는 구성이 좋습니다.

손민준

자동화, API, LLM, 크롤링, 다양한 토이 프로젝트 경험

Logic
API 자동화 LLM 활용 결과 생성
  • 강점: 크롤링, 분실물 서비스, Spotify 자동 포스팅, YOLO 축구 분석, Gemini/Notion 자동화 등 작은 문제를 제품처럼 풀어본 경험이 많습니다.
  • 역할: 어깨 나이 테스트의 점수 로직, 결과 문구 생성, 공유 페이지, LLM 기반 결과 해석 프로토타입.
  • 주의: 협업이 어색할 수 있으므로 작은 이슈 단위와 주간 데모로 리듬을 잡아줍니다.

C#/C++, AI API 활용, 프롬프트 엔지니어링 관심

AI UX

  • 역할: Unity WebGL 또는 웹 기반 테스트 인터랙션, 카메라 측정 안내 흐름, 프롬프트 기반 결과 해석 문구.
  • 주의: AI 모델 개발자처럼 쓰기보다, AI를 제품 경험에 녹이는 역할로 잡는 편이 자연스럽습니다.

이수빈

편입 초기, Unity/C# 학습, C/C++ 기초, 관심 분야 탐색 중

Game
Unity/C# C/C++ 상태 관리 초기 성장형
  • 강점: 아직 프로젝트 경험은 적지만 게임 개발 동아리에서 Unity/C#을 배우고 있고, 다른 언어에 대한 거부감이 없습니다.
  • 역할: 어깨 챌린지의 간단한 게임형 화면, 설문 상태 관리, 테스트 케이스, 결과 타입별 UI 정리.

6~8주 실행 로드맵

두 팀 모두 매주 보이는 결과물을 내게 해야 합니다. R&D 팀은 실험 로그, 바이럴 팀은 화면 데모 중심으로 관리합니다.

1주차

문제 정의와 역할 확정

R&D 팀은 측정 환경과 샘플 데이터 기준을 잡고, 바이럴 팀은 어깨 나이 테스트의 화면 흐름과 문항 초안을 만듭니다.

2~3주차

1차 프로토타입

이형진은 ROM 측정 실험 노트를, 박하준은 측정 환경 기록표를, 바이럴 팀은 설문 결과 페이지와 점수 로직을 냅니다.

4~5주차

카메라 선택 측정 연결

브라우저 카메라 권한, 팔 올리기 안내, 측정 실패 시 설문 결과로 대체되는 안전 흐름을 붙입니다.

6~7주차

공유와 전환 설계

결과 공유 문구, 시니어바이브 정밀 측정 권유, 관리자 확인용 테스트 로그를 정리합니다.

8주차

대표 보고 패키지

ROM 실험 리포트, MVP 데모 URL, 바이럴 확장 가능성, 학생별 계속 활용 여부를 한 문서로 마감합니다.

대표 의사결정 포인트

지금 정하면 좋은 것

바이럴 MVP의 목표를 “예약 전환”으로 볼지 “브랜드 노출/공유”로 볼지 먼저 정해야 합니다. 초기 산학협력 과제는 브랜드 노출과 고객 반응 확인에 두고, 예약 전환은 2차 목표로 두는 편이 부담이 낮습니다.

리스크 관리

카메라 ROM 측정은 재미있는 기술 체험으로만 표현하고, 정확도나 진단을 약속하지 않습니다. 원본 의료 데이터와 파트너 정보는 학생에게 바로 열지 말고 익명화 샘플과 테스트 계정부터 제공합니다.

작성 기준: 산학협력 학생 미팅 메모. 연락처와 학번 등 개인정보는 공유 페이지에서 제외했습니다.
